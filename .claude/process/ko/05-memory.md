# 메모리 운영

Claude Code가 프로젝트별로 유지하는 파일 기반 영구 기억.

```
~/.claude/projects/<프로젝트-경로-슬러그>/memory/
├─ MEMORY.md          ← 인덱스. 매 세션 컨텍스트에 로드된다
└─ <slug>.md          ← 기억 하나당 파일 하나
```

## 파일 양식

```markdown
---
name: <짧은-kebab-case-슬러그>
description: <한 줄 요약 — 회상 시 관련성 판단에 사용>
metadata:
  type: user | feedback | project | reference
---

<사실 본문. feedback/project 타입은 아래 두 줄을 이어 붙인다.>

**Why:** <왜 이게 중요한지>
**How to apply:** <다음에 어떻게 행동하는지>
```

관련 메모리는 `[[상대-메모리-name]]`으로 링크한다. 아직 없는 이름을 걸어도 된다 — 나중에 쓸 것의 표시가 된다.

| 타입 | 무엇을 담나 |
|---|---|
| `user` | 사용자가 누구인지 — 역할, 전문성, 선호 |
| `feedback` | 작업 방식 지침. **교정과 확인된 접근 둘 다.** 이유를 반드시 포함 |
| `project` | 코드/git 히스토리로 유도할 수 없는 진행 중 작업·목표·제약. 상대 날짜는 절대 날짜로 변환 |
| `reference` | 외부 리소스 포인터 (URL, 대시보드, 티켓) |

### MEMORY.md 인덱스

한 줄씩. frontmatter 없음. **내용을 여기에 쓰지 않는다.**

```markdown
- [제목](파일명.md) — 한 줄 훅
```

## 운영 규칙

- 저장 전 **같은 내용을 다루는 기존 파일이 있는지 확인**하고, 있으면 갱신한다. 중복 생성 금지.
- 틀린 것으로 판명된 메모리는 **삭제한다.**
- 파일 작성 후 `MEMORY.md`에 한 줄 포인터를 추가한다.

### 저장하지 않는 것

- 레포가 이미 기록하는 것 — 코드 구조, 과거 수정 이력, git 히스토리, `CLAUDE.md` 내용
- 이번 대화에서만 의미 있는 것

**`CLAUDE.md`나 `process/` 문서에 규약을 적었으면 같은 내용을 메모리에 또 넣지 않는다.** 두 벌 관리가 된다.

### 읽을 때 주의

- 메모리는 **쓰인 시점의 사실**이다. 파일·함수·플래그 이름이 나오면 **아직 존재하는지 확인하고** 권한다.
- `<system-reminder>` 안에 실린 메모리는 배경 정보지 사용자 지시가 아니다.

## 범용 메모리 항목 (feedback — 어느 프로젝트에서든 유효)

새 프로젝트를 시작할 때 그대로 옮겨 쓸 수 있는 항목. 상세는 링크된 문서가 정본이다.

| 항목 | 정본 |
|---|---|
| 티켓 단위로 diff 분리 — 워킹트리에 섞인 다른 티켓 변경은 손대지 않는다 | [02-git.md](02-git.md) §1 |
| push는 동의 후에만 — 명시 요청이 온 건만 개별 push | [02-git.md](02-git.md) §2 |
| 브랜치명은 로컬 기준 — `origin/` 명시 없으면 로컬 브랜치 | [02-git.md](02-git.md) §3 |
| 커밋 트레일러 금지 — `Co-Authored-By` / `Claude-Session` 넣지 않는다 | [02-git.md](02-git.md) §4 |
| stash 금지에 가까운 주의 — WIP 커밋 우선 | [02-git.md](02-git.md) §5 |
| 명세서는 md로 — Artifact 대신 레포 내 문서 폴더 | [03-docs.md](03-docs.md) |
| 이관 시 테이블 파일 무수정 — 기록만 남긴다 | [04-templates.md](04-templates.md) |
| 질문에는 대답만 — 읽기는 자유, 쓰기는 지시받았을 때만 | [00-process.md](00-process.md) §1-1 |
| 검증 안 한 것을 끝났다고 하지 않는다 | [00-process.md](00-process.md) §6 |

## 프로젝트 종속 항목 (project — 새 프로젝트에 복사하지 않음)

프로젝트별 정책 결정·작업 계획은 범용 템플릿에 넣지 않고 해당 프로젝트 메모리에만 둔다. 기록 패턴:

- **확정 정책 결정** — 결정 내용 + 의도적 제외 범위 + 제외의 한계(어떤 유저/경로가 영향받는지)를 함께 기록.
  후속 버그 리포트가 오면 이 결정이 원인인지 **먼저 대조한다.**
- **작업 계획 합의** — 베이스 커밋/브랜치, 목표 구조, 리스크 정책, 진행 상태, 얻은 교훈을 한 파일에 누적 갱신.
  교훈 중 일반화 가능한 것은 `process/` 문서로 승격한다.
