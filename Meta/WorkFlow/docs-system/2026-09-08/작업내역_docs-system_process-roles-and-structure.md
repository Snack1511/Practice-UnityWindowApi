# 문서 체계 정비 — process · roles · roadmap · .claude 재편 (2026-09-07~08)

> 작업 명세 문서. 상세는 이 문서가 정본이고, [docs/CHANGELOG.md](../../../docs/CHANGELOG.md)는 시간순 인덱스다.

코드가 아니라 **문서와 규약만** 바꾼 작업이다. 한 세션에서 연속으로 진행됐고 서로 물려 있어 한 항목으로 묶었다.

시작점은 `CLAUDE.md` 하나에 프로젝트 소개·규약·절차·모델 규약·검증 절차가 전부 들어 있던 상태(213줄)다.
매 세션 자동으로 읽히는 문서라 길이가 그대로 비용이었고, 다른 프로젝트로 옮길 수 있는 부분과
이 프로젝트에서만 참인 부분이 섞여 있었다.

바탕화면 `Desktop/Claude` 아래 흩어져 있던 규약 문서를 하나로 합쳐 들여왔다.

### 통합하며 해소한 충돌

원본들이 서로 어긋나던 지점. **바꾼 쪽이 아니라 이긴 쪽을 기록했다.**

| 쟁점 | 결정 | 근거 |
|---|---|---|
| 커밋 트레일러 | **금지** | 사용자 규칙이 하네스 기본 지침보다 우선 |
| 명세 문서 Artifact 발행 | **금지**, 레포 내 md | 팀 문서 흐름 밖으로 나가고 레포에 안 남는다 |
| `docs`+`advise` vs 작업 명세 | **둘 다 유지, 역할 분리** | 코드베이스 설명 vs 작업 단위 기록 |
| 메모리 문서 2벌 | **하나로 병합** | 형식 설명이 거의 같았다 |
| `Extra Rules.txt` | **주제별로 분해** | 한 파일에 섞여 어느 상황에 적용되는지 안 보였다 |

### 이중 언어 (en/ko)

에이전트는 `en/`을 읽고 사용자는 `ko/`로 검토한다.
교차 배치된 한 파일이 아니라 두 파일로 나눈 이유는 **어긋남이 드러나게 하기 위해서**다.
파일명과 섹션 번호를 언어 간 동일하게 맞춰서 한쪽만 갱신되면 diff 에 바로 보인다.
양쪽 동시 갱신 규칙은 `07-rule-pipeline` 에 조항으로 넣었다.

## 2. `roles/` — 프로젝트 고유 규약 분리

`process/` 도입 후에도 `CLAUDE.md` 가 절차성 서술을 들고 있어 중복이 생겼다.

**경계는 "복사하면 그대로 쓸 수 있나"다.**

| | `process/` | `roles/` |
|---|---|---|
| 성격 | 어느 프로젝트에서든 통하는 **절차** | 이 프로젝트에서만 참인 **값** |
| 예 | "검증 5단계를 밟고 안 한 건 안 했다고 적는다" | "컴파일 검사는 이 Unity 경로로 이 명령을 쓴다" |
| 이동 | 새 프로젝트에 복사해 그대로 씀 | 복사하면 전부 틀린 값이 됨 |

`process/` 의 플레이스홀더를 채운 결과가 `roles/` 다.
`coding.md` · `model.md` · `verification.md` 세 문서로 갈랐다.

**함정 섹션은 일부러 `CLAUDE.md` 에 남겼다.** `CLAUDE.md` 만 매 세션 자동으로 읽힌다.
폴더로 빼면 링크를 따라가야 보이는데 이 프로젝트의 함정은 **안 읽으면 조용히 실패하는** 종류다 —
씬 등록 누락, `#if` 블록, `UnityEditor` 참조. 전부 컴파일 에러 없이 런타임에 터진다.

결과: `CLAUDE.md` 213 → 108 → **55줄**.

## 3. `docs/roadmap.md` — 두 축 로드맵

사용자가 제공한 구조 축(시스템·모듈·오브젝트)과 시간 축(0~9단계)을 한 문서에 담고,
기존 코드에 전수 대조해 현황을 박았다.

```
시스템   ██████░░░░░░  1 완료 · 3 부분 · 2 없음
모듈     ░░░░░░░░░░░░  0 / 5   (grep 전수 확인, 코드 0건)
오브젝트 ░░░░░░░░░░░░  0 / 7
```

### 대조에서 읽어낸 것

1. **순차가 아니라 병렬 절반이다.** 0~4 중 완전히 닫힌 단계가 하나도 없다.
   5단계에서 1~4의 미결이 한꺼번에 터진다.
2. **7단계가 1·2를 갈아엎는다.** "외부 로컬DB, 정석적인 리소스 관리"는 지금의
   CSV + `Resources/` 를 교체한다는 뜻이다. 1·2단계에서는 구현보다 **경계**를 먼저 잡아야 한다.
   특히 세이브 스키마 버전은 처음부터 넣어야 한다 — 나중에 넣으면 마이그레이션이 필요해진다.
3. **5단계가 압도적으로 크다.** 모듈 5종과 오브젝트 7종이 전부 여기 몰려 있다.

### 단계별 닫힘 기준

**기준은 실행이나 명령으로 확인 가능해야 한다.** "잘 동작한다"는 기준이 아니다.

| # | 판정 방법 |
|---|---|
| 0 | 로비↔메뉴 3회 왕복 후 로드된 씬 수가 늘지 않는다 |
| 1 | 저장 → 종료 → 재실행 → 복원. 저장 중 강제 종료해도 기존 파일 생존 |
| 2 | `grep -rn "Resources\.Load" Assets/Script` 결과가 `ResourcesManager` 두 줄뿐 |
| 3 | 타이틀 → 메뉴 → 로비까지 클릭만으로 도달 |
| 4 | 씬 전환 10회 후 예외 0건 + 저장값 복원 |
| 5 | 플레이 루프 1회전 완주 |
| 6 | 이펙트 재생 반복 후 오브젝트 수 원복 |
| 7 | 클린 클론에서 명령 하나로 빌드 산출 |

2단계 판정 명령을 실제로 돌려 **위반 3곳**을 확인해 표로 박았다 —
`SpriteController:18`, `LoadingScene:44`, `Loader.cs:31`.
`Loader<T>` 는 로더 역할이지만 `ResourcesManager` 캐시를 우회해 같은 에셋이 중복 로드된다.

8단계는 닫힘 기준을 지금 정할 수 없다고 명시했다. 9단계는 종료 조건이 없는 단계다.

## 5. `.claude/` 구조 재편

디렉토리 내에서 전역 참조할 목적으로 문서를 한곳에 모았다.

```
CLAUDE.md              루트 고정 — 자동으로 읽히는 건 루트뿐이다
.claude/
├─ HandOff.md
├─ ChangeLog/          작업 명세 축
├─ docs/               코드베이스 축
├─ advise/  roles/  process/
└─ settings.json
```

`ChangeLog/` 를 `docs/` 밑이 아니라 형제로 뒀다. `process/03-docs.md` 가 문서를 두 축으로 가르는데,
ChangeLog 는 두 번째 축이라 코드베이스 축 밑에 들어가면 성격이 섞인다.
범용 이름 `WorkFlow/` ↔ 이 프로젝트 구현 `ChangeLog/` — `process` ↔ `roles` 와 같은 대응이다.

`docs/CHANGELOG.md` 356줄 5항목을 영역별로 쪼개고, 본문은 **39줄 시간순 인덱스**로 축소했다.
상세는 `ChangeLog/` 가 정본, 인덱스는 링크와 한 줄 요약만.

`docs/models/` → `docs/model-guides/`. `roles/model.md` 와 이름이 겹쳤다.

### 링크 검증에서 걸린 함정

폴더가 통째로 이동해 `.claude/` 내부 상대 경로는 대부분 그대로였다. 실제 깨진 4종만 고쳤다.

**잔여 12건은 일부러 손대지 않았다.** `process/01-rules.md` 의 `CLAUDE.md` 템플릿과
`process/05-memory.md` 의 `MEMORY.md` 형식 예시로, **코드블록 안 다른 프로젝트용 예시**다.
일괄 치환했다면 `process/` 의 범용성이 깨졌다.

## 6. HandOff 재작성

세션 전체를 훑어 **제안했지만 답을 받지 못한 15건**을 전수 수집해
A(막힘 3) · B(정리 4) · C(설계 5) · D(정보 2) · E(반쯤 1) 로 분류했다.

항목마다 **묻는 내용 / 선택지 / 안 정하면 막히는 것**을 함께 적었다.
답만 받으면 바로 실행할 수 있는 형태여야 순차 처리가 굴러간다.

"한 번에 하나만 묻고 목록 전체를 나열하지 않는다"를 문서 머리에 박았다.
조건부 보류 3건은 재개 조건이 정해져 있어 **묻지 않는다**로 분리했다.
