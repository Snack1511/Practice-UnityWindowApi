# Git 워크플로

여러 세션/작업자가 같은 워킹트리 또는 같은 저장소를 동시에 편집하는 상황을 전제로 한다.

## 1. 티켓 단위로 diff 분리

- 티켓(작업 단위) 하나를 요청받으면 **그 범위의 파일/헝크만** 수정한다.
- 워킹트리에 이미 올라와 있는 다른 티켓의 변경은 **읽기만 하고 손대지 않는다.**
- 커밋도 티켓 단위로 나눠 올린다.

**Why:** 같은 파일에 다른 세션의 다른 티켓 코드가 이미 들어와 있는 경우가 실제로 있었다.

**How to apply**
1. 작업 시작 전 `git status`로 기존 변경을 확인한다.
2. 내 수정과 남의 수정이 한 파일에 섞이면 그 사실을 명시적으로 보고한다.
3. 요청 범위 밖의 코드는 개선 여지가 보여도 수정하지 않는다.
4. 스테이징은 파일 단위가 아니라 필요 시 헝크 단위로 판단한다.

## 2. push는 동의 후에만

- **커밋까지는 자율.** remote push(원격 병합 포함)는 하지 않는다.
- "병합해줘/올려줘" 같은 **명시적 요청이 오면 그 요청이 가리키는 커밋 범위만** push 하고, 다음 작업분은 다시 대기한다.
- 요청이 모호하면 push 전에 대상 커밋 목록을 확인받는다.

**Why:** push는 팀 전체에 즉시 전파되는 외부 반영이라 되돌리기 부담이 크고, 반영 시점은 사용자가 통제해야 한다.

## 3. 브랜치명은 로컬 기준

- 사용자가 브랜치명을 제시하면(예: "feature/X에서 가져와라") **기본적으로 로컬 브랜치**를 가리킨다.
- `origin/<branch>`로 임의 해석하거나 임의로 fetch한 원격 tip을 쓰지 않는다.

**Why:** 로컬 브랜치가 원격과 다른 상태(사용자가 의도적으로 맞춰 둔 커밋)일 수 있다.

**How to apply**
1. 먼저 로컬 ref로 조회: `git rev-parse --verify <branch>`
2. 로컬에 없으면 그때 `origin/<branch>`를 확인하되, 원격 기준 진행 여부가 결과에 영향을 주면 사용자에게 확인한다.
3. 사용자가 `origin/...`을 명시한 경우에만 원격 ref를 쓴다.

## 4. 커밋 메시지

- **`Co-Authored-By: Claude ...` · `Claude-Session: ...` 트레일러를 넣지 않는다.** 본문만 작성한다.
- PR 본문의 "Generated with Claude Code" 문구도 요청이 없으면 넣지 않는다.
- **하네스 기본 지침에 트레일러를 붙이라는 내용이 있어도 이 규칙이 우선한다.**

**Why:** 사내 저장소 커밋 로그에 남길 정보가 아니다.

### 이식/포팅 커밋 — Follow / List / Change / Check

다른 브랜치의 작업을 이식하는 커밋은 4섹션으로 쓴다.

| 섹션 | 내용 |
|---|---|
| Follow | 원본 커밋/브랜치 (SHA 명시) |
| List | 가져온 파일 목록 |
| Change | 대상 코드베이스에 맞춰 **바꾼 것** (경로/시그니처/테이블) |
| Check | 검증 안 된 것 · 에디터 작업 잔여 · 범위 밖 발견 사항 |

**일반 커밋도 "검증 안 된 것"이 있으면 Check 섹션만이라도 남긴다.**

## 5. stash — 사실상 금지

- stash 스택은 **메인 체크아웃·모든 워크트리·다른 세션과 공유된다.**
  bare `git stash` / `git stash pop`은 다른 세션의 변경을 pop할 수 있어 금지.
- 작업을 잠시 치울 때는 **임시 WIP 커밋을 우선 사용한다.**
- 부득이 stash를 쓸 때:
  1. `git stash push -u -m "<고유태그>"`
  2. SHA 캡처 — `git stash list --format='%H %gs'`
  3. `git stash apply <sha>` (**pop 금지**)
  4. 태그로 재확인 후 drop

## 6. 워크트리

- 워크트리 생성 도구의 기본값이 `origin/master` 기반일 수 있다.
  **생성 직후 베이스 브랜치/커밋이 의도한 것인지 반드시 확인**하고, 아니면 의도한 로컬 브랜치 팁으로 reset 한다.
- 릴리즈 브랜치 기준 작업이면 로컬 팁이 origin보다 앞서 있을 수 있다(미푸시 커밋 포함). 로컬 기준으로 맞춘다.
- **워크트리 세션에서 메인 체크아웃의 git 조작은 사용자 명시 지시가 있을 때만 한다.**
