# Opus 4.8 작업 규약

`/opus48`로 실행할 때. 공통 원칙은 [README](README.md), 모델 선택 기준은 [CLAUDE.md](../../../CLAUDE.md).

Opus 5와 **가격이 같다**($5/$25). 성능 계단이 아니라 동작 차이로 고르는 모델이다.
장기 에이전트 작업, 지식 작업, 비전, 메모리가 강점. Opus 5보다 **도구를 덜 잡고 서브에이전트를 덜 띄운다.**

Opus 5 규약이 "과잉을 깎는" 것이라면, 이건 **부족을 채우는** 규약이다.

## 넣어야 하는 지시

### 1. 도구 사용 트리거를 명시한다

4.8은 도구 호출보다 **추론을 선호한다.** 대부분의 경우 더 나은 결과지만, 도구가 필요한 상황에서도 안 잡는다.
"쓸 수 있다"가 아니라 **"언제 쓰라"**를 적어야 한다.

> 현재 정보가 답을 바꾸는 질문(패키지 버전, Unity API 변경, 최근 이슈)은 답하기 전에 검색한다.

### 2. 위임 트리거를 명시한다

서브에이전트를 기본적으로 적게 띄운다. Opus 5와 정반대라 같은 지시를 쓰면 안 된다.

> 한 응답으로 끝낼 수 있는 일에는 서브에이전트를 쓰지 않는다 — 이미 보고 있는 함수를 고치는 것 같은 일. 여러 파일에 병렬로 퍼지는 조사에는 같은 턴에 여러 개를 띄운다.

### 3. 사소한 결정은 묻지 않고 진행한다

Opus 4.7보다 **더 자주 멈춰서 묻는다.** 변수명, 기본값, 동등한 두 방식 중 선택은 합리적인 쪽을 고르고 한 줄로 알린다.

계속 물어야 하는 것: 범위 변경, 되돌리기 어려운 작업(파일 삭제, git 강제 push, 씬 파일 덮어쓰기), 사용자만 답할 수 있는 설계 판단.

### 4. 적용 범위를 명시한다

지시를 **문자 그대로** 해석한다. 한 항목에 대한 지시를 다른 항목으로 알아서 확장하지 않고, 하지 않은 요청을 추측하지 않는다.
정밀함이 장점이지만, 넓게 적용되길 원하면 그렇게 적어야 한다.

- ❌ `이 매니저 초기화 순서 고쳐줘`
- ✅ `MainProcess의 Initialize/Release 양쪽 전부 고쳐줘. 하나만이 아니라`

### 5. 실패는 3회까지 시도하고 보고한다

"성공할 때까지 반복"은 금지 — 정지 조건이 없다. 같은 에러가 3번 반복되면 원인 가설과 막힌 지점을 보고하고 멈춘다.
사용자만 풀 수 있는 블로커(에디터 설정, 빌드 환경, 설계 결정)는 떠넘기는 게 아니라 **정확한 보고**다.

## 넣지 말아야 하는 지시

### 중간 보고 강제

시키지 않아도 도구 호출 사이에 상황을 설명한다. "N번마다 요약하라" 같은 지시는 이미 충분한 서술을 과잉으로 만든다.
반대로 너무 장황하면 억제한다:

> 도구 호출 사이에는 기본적으로 침묵. 뭔가 찾았거나, 방향을 틀거나, 막혔을 때만 한 문장. 끝나면 결과만 한두 문장.

### 코드 리뷰의 "심각한 것만"

Opus 5와 동일한 함정. 지시를 문자 그대로 따라서 찾아낸 버그를 보고하지 않는다.

> 확신이 없거나 사소하다고 판단되는 것도 전부 보고한다. 이 단계에서 중요도로 거르지 않는다. 각 항목에 확신도와 심각도를 붙인다.

## 참고

- **thinking이 기본으로 꺼져 있다.** Opus 5·Sonnet 5와 다르다.
- **effort가 이전 Opus보다 더 크게 작용한다.** 코딩·에이전트는 `xhigh`, 판단이 중요한 작업은 최소 `high`.
- **추론이 얕으면 프롬프트를 고치지 말고 effort를 올린다.**
- **프론트엔드 기본 스타일이 강하다** — 크림색 배경(`#F4F1EA` 계열), 세리프 제목. 이 프로젝트의 오버레이 UI에는 안 맞을 수 있다. "깔끔하게"가 아니라 색상값과 폰트를 직접 지정한다.
