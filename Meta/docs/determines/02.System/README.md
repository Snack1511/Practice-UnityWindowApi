# 02. System — 시스템 정의

여러 콘텐츠가 같이 쓰는 기능이다. 계층 규칙은 [roadmap.md](../../roadmap.md) §1 —
**여러 콘텐츠가 동시에 필요로 하면 시스템**이다.

## 인벤토리 시스템

던전 · 광산 · 마을이 모두 쓰므로 모듈이 아니라 **시스템**이다 (C-1 결과).
경제 시스템은 따로 두지 않는다 — 재화가 아이템이므로 인벤토리가 다룬다 (C-4).

### 아이템 (C-4, 2026-10-29)

```
Item { id, type, count }
  type: Equipment | Consumable | Currency
```

- **재화는 아이템의 한 타입(`Currency`)이다.** 골드 · 광석 · 보석 등 재화가 여러 종일 수 있다.
- **보상 · 소모는 아이템 단위로만 지급·소모한다.** 재화인지 따지지 않는다.

```
Give(itemId, n)   // 보상 모듈
Take(itemId, n)   // 소모 모듈
```

### 보관 위치

| 칸 | 담는 것 | 형태 |
|---|---|---|
| **배낭 격자** | `Equipment` · `Consumable` | 아이템이 격자 칸을 차지한다 |
| **재화 칸** | `Currency` | 격자 밖. 종류별 개수만 쌓인다 |

`Give` / `Take` 는 아이템 타입을 보고 **인벤토리가 칸을 고른다.** 호출하는 쪽은 칸을 모른다.
재화를 격자 밖에 둔 이유는 대량 재화(골드 10만 등)가 격자를 덮지 않게 하기 위해서다.

### 배낭 표시 — UI (C-2, 2026-10-29)

- 배낭 격자 · 슬롯 · 아이템은 **UI 로 그린다.** `UIRoot` 의 `Window` / `Popup` 레이어.
- 데이터는 인벤토리 시스템이 갖고, UI 는 그 데이터를 보여주기만 한다.
- 이유: 격자 배치 · 드래그 · 하이라이트는 UI 가 원래 잘하는 일이다. 전역 `EventSystem` 이 이미 있고,
  나중에 "그려진 곳만 클릭을 받는" 히트 테스트를 만들 때도 UI 레이캐스트 한 경로만 보면 된다.
- 결과: 로드맵의 오브젝트 7종 중 배낭 3종(격자 · 슬롯 · 아이템)이 UI 로 옮겨가 **오브젝트는 4종**이 된다.

## 미확정

- (미확정) 재화 종류 목록 — 골드 · 광석 · 보석은 예시다.
- (미확정) 배낭 격자 크기와 확장 여부.
- (미확정) 아이템 모양 — 칸 하나짜리만 있는지, 여러 칸을 차지하는 모양(1x3 등)이 있는지.
