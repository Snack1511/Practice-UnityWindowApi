# 01. Policy — 기획 정책

모든 시스템과 콘텐츠가 지키는 규칙이다.

## RNG 재현성 — 콘텐츠별 상태 저장 (C-3, 2026-10-29)

- 무작위를 쓰는 콘텐츠(던전 · 광산 · 마을)는 **각자 RNG 를 하나씩** 갖는다.
  마을은 2026-11-06 에 약탈 시뮬레이션이 정해지면서 추가됐다.
- RNG 의 내부 상태를 **세이브에 저장**한다. 저장 → 종료 → 재실행해도 다음 결과가 같다.
- 목적은 둘이다.
  - **저장·불러오기를 반복해 좋은 결과를 노리는 리롤 차단.**
  - **버그 재현.** 이 프로젝트는 실패가 런타임에만 드러나므로 같은 상태를 다시 만들 수 있어야 한다.
- 구현 제약: `System.Random` 은 내부 상태를 꺼낼 수 없다. 상태가 `uint` 하나인 xorshift 를 직접 쓴다.
- `UnityEngine.Random` 은 전역 하나라 콘텐츠끼리 섞인다. 게임 로직에는 쓰지 않는다 (연출용은 허용).

```
SaveData {
  schemaVersion: 1,
  rng: { dungeon: <uint>, mine: <uint>, village: <uint> },
  ...
}
```

## 세이브 스키마 버전 — 처음부터 넣는다

나중에 넣으면 기존 세이브 마이그레이션이 필요해진다. 근거는 [advise/003](../../../advise/003-data-layer.md) 3-5.

## 콘텐츠 오브젝트는 런타임 생성 (C-5, 2026-10-29)

- 콘텐츠가 켜질 때(`ActiveContent(true)`) 프리팹을 `ResourcesManager` 로 불러 자기 GameObject 밑에 만들고,
  꺼질 때(`ActiveContent(false)`) 파괴한다.
- **씬에 배치하지 않는다.** 콘텐츠는 씬이 아니라 `DontDestroyOnLoad` 인 `ContentManager` 밑에 살기 때문에
  씬 오브젝트와 수명이 어긋난다. UI 를 전역 `UIRoot` 밑으로 옮긴 것과 같은 판단이다.
- 대상: 이동 캐릭터 · 전투단 · 스크롤 배경 · 이벤트 오브젝트 (4종).
